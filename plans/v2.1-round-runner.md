# v2.1 — extract the round runner out of SKILL.md

**Status:** revised after adversarial review (round 6); ready to implement
**Closes:** review finding 2 (quota fallback dead from round 2), and the
orchestration half of finding 4 (retry-once never wired in)

## Problem

SKILL.md steps 1 and 2 implement the round: build the prompt, detect the
transport, invoke the reviewer, and on OpenAI quota exhaustion rebuild for the
Claude calibration and re-invoke. That logic lives as Python embedded in
Markdown prose, which has produced two defects and blocks the fix for a third:

1. **The quota fallback is dead from round 2 onward.** The rebuild's argument
   list contains a *comment* where `--diff-file` should be. The builder rejects
   `--round > 1` without `--diff-file` and returns 2; `check=True` then raises
   before the Claude invocation is reached. This capability is advertised in the
   skill's own `description` frontmatter.
2. **No test can reach it.** Nothing imports a Markdown code block, so the
   defect above survived every green suite.
3. **Retry-once has nowhere to live.** `TransportError.kind` now classifies
   retryable failures, but step 2 catches only `QuotaExhaustedError`.

Round context is also duplicated: step 1 assembles the builder arguments and
the fallback in step 2 must reassemble the same set. That duplication is what
the comment-instead-of-argument bug grew in — and the review of this plan's
first draft found the same class of omission *in the plan*, for a different
argument (`--diff-recovered-from-git`). The lesson is that no fix works unless
the argument list is constructed exactly once.

## Approach

One importable function owns the round: it takes the context once, derives
everything else, and returns an outcome the later phases can persist truthfully.

New file `scripts/run_review_round.py`:

```python
@dataclass(frozen=True)
class RoundRunOutcome:
    result: ReviewResult          # the successful response
    transport: str                # the transport that actually produced it
    total_cost_usd: float         # summed over EVERY attempt, not just the winner
    tokens_input: int             # likewise
    tokens_output: int            # likewise
    attempts: list[AttemptRecord] # (transport, kind_or_None, cost) per try
    prompt_debug_path: Path       # unique per run; see Temp files


def run_review_round(
    *,
    repo_root: Path,              # REQUIRED and authoritative
    slug: str,
    version: str,
    round_n: int,
    selection: TransportSelection,
    consistency_only: bool = False,
    cumulative_cost_usd: float = 0.0,
    keep_prompt: bool = False,
) -> RoundRunOutcome:
```

`skill_dir` is derived from `Path(__file__).resolve().parent`, never accepted —
an accepted path is both a split authority and an injection surface.
`plan_file`, the sidecar dir, the snapshot dir and both subprocess cwds all
resolve beneath `repo_root`, so a round cannot build from one repository,
recover snapshots from another, and invoke Claude in a third.

Whether the quota fallback is permitted is carried by `selection` (its `reason`
already distinguishes an explicit `ADVERSARIAL_TRANSPORT` from auto-detection);
the runner does not take a second transport argument that could disagree with
the first.

### Round build context — captured once

For `round_n > 1` the runner calls `compute_round_diff(...)` itself and holds
**both** returned values in one immutable context:

```python
@dataclass(frozen=True)
class _BuildContext:
    diff_path: Path | None
    diff_recovered_from_git: bool
    consistency_only: bool
    cumulative_cost_usd: float
```

`_build_prompt(transport_name) -> str` is the **only** place builder argv is
assembled. It emits `--diff-file` when `diff_path` is set,
`--diff-recovered-from-git` when the flag is true, `--consistency-only` and
`--cumulative-cost-usd` from the context, and `--transport transport_name`.
The initial build and the fallback rebuild both call it; neither re-types an
argument list. Preserving the diff bytes while dropping the recovery flag would
keep the prompt syntactically fine and silently change its meaning, so the flag
travels with the text by construction rather than by discipline.

### Attempt policy — non-recursive, hard-bounded

```
attempt on selected transport
  success                      -> done
  QuotaExhaustedError          -> fallback (auto-detected + Claude CLI only)
  retryable                    -> ONE more attempt on the same transport
  non-retryable / 2nd failure  -> raise
fallback: rebuild for "claude", then the same policy once more
```

Retryable means a `TransportError` whose derived `is_transient` is true
(`max_turns`, `max_budget`, `api`) **or** a `ReviewSchemaError`. The schema case
matters and the first draft missed it: SKILL.md and the README both promise one
retry for malformed reviewer output, that output was already paid for, and the
Claude path parses directly. Wiring only transport retries would leave a
documented half of D20 dead.

Never retried: `wall_timeout` (a retry inherits the same timeout),
`permanent`, and `quota` (which is a transport switch, not a retry).

Hard ceiling: **at most 2 attempts on the original transport, at most 1
fallback switch, at most 2 attempts on Claude** — 4 calls worst case. Enforced
by a counter, not by recursion.

### Cost accounting

Every attempt that reports usage contributes to the outcome's totals, including
attempts that then raised. A `max_turns` / `max_budget` error envelope can carry
`total_cost_usd`, and a malformed success consumed tokens before
`ReviewSchemaError` was raised; recording only the winning call can undercount a
round by close to half. `_raise_on_claude_error_envelope` currently raises
before usage extraction, so the retryable paths must attach the reported cost to
the error (or extract it before raising) for the runner to sum.

SKILL.md step 6 persists `RoundRunOutcome.total_cost_usd`, not
`result.usage.cost_usd`.

## Non-goals

- No change to `reviewer.py`'s transport behaviour, prompt content, sidecar
  schema, or exit gates.
- Step 6 persistence and step 7 exit evaluation stay in SKILL.md. The review
  confirmed these are separate state-machine phases, not part of this seam.
- `build_reviewer_prompt_v2.py` keeps its CLI; the runner shells out to it so
  the documented manual-debugging path keeps working.
- **Known, out of scope:** SKILL.md derives the running cumulative cost by
  regex-scraping `cumulative: \$N` out of the *rendered* fixes-md, even though
  `cost_tracker.restore_cumulative_from_sidecars()` reads it from the
  authoritative sidecars. That round-trips an authoritative number through a
  lossy presentation layer. It belongs to the persistence phase; file it as
  follow-up rather than widening this seam.

## Temp files

No fixed `/tmp/round-N-*.txt`. Two concurrent reviews at the same round number
would overwrite each other's prompt or diff between build and invoke — a
cross-repository review, or plan text left readable after the run. The runner
uses a per-run `TemporaryDirectory`, passes prompt text to `invoke_reviewer` in
memory, exposes the path as `RoundRunOutcome.prompt_debug_path`, and cleans it
unless `keep_prompt=True`. SKILL.md's troubleshooting section points at the
reported path instead of a hardcoded one.

## Tests

The point of the extraction is that these become writable.

**Integration (the one that would have caught the original defect):**

1. Real round-1 sidecar + snapshot fixtures; run a **real** round-2 build
   through the builder CLI; mock only `invoke_reviewer`, raising
   `QuotaExhaustedError` first and returning a Claude result second. Assert the
   second prompt actually contains the round-2 diff, the prior-round context,
   the Claude calibration blocks, and the consistency/cost values. A test that
   asserts against a mocked builder would pass while the builder still exits 2,
   which is exactly how the defect survived.
2. Same, with `recovered_from_git=True`: both prompts carry the degraded-diff
   warning.

**Policy:**

3. `api → quota → claude api → success` records 4 attempts and sums their costs.
4. Two failures on the same transport surface the second error; attempt count
   never exceeds the ceiling.
5. Per kind: `max_turns` / `max_budget` / `api` / `ReviewSchemaError` invoke
   twice; `wall_timeout` / `permanent` invoke once.
6. Explicit `ADVERSARIAL_TRANSPORT=openai` + quota exhaustion re-raises rather
   than falling back; likewise when no Claude CLI is available.
7. Round 1 passes no `--diff-file`; round 2 passes one.
8. Two runners at the same round number do not share a prompt path.

## Risks

- **SKILL.md drift.** The prose must match the new signature or the loop breaks
  in a way no test catches — the same class of failure this plan fixes. Keep the
  snippet to a single call with named arguments so a mismatch is visible.
- **Orchestrated mode.** `/ship` invokes this skill; the runner must not prompt,
  print interactively, or change exit codes.
- **Cost attribution needs a reviewer.py touch.** Attaching reported cost to
  raised errors is the one place this plan reaches outside SKILL.md, and it is
  the part most likely to be got subtly wrong.
